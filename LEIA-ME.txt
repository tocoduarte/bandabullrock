BULLROCK - SITE ESTÁTICO (Cloudflare Pages)
==========================================

O QUE ALTERAR NO DIA A DIA
Só o arquivo config.json. O index.html não precisa ser tocado.

- pixPeriodos: datas em que o botão Pix aparece (dd/mm/aaaa, início e fim
  inclusivos, sempre no horário de Brasília). Período inválido é ignorado.
- pix: preencha UMA das formas:
    url ............ link de pagamento de um provedor (abre direto)
    copiaECola ..... código "Pix Copia e Cola" gerado no app do banco
    chave + favorecido + cidade ... o site gera o Copia e Cola
                     (valor vazio = a pessoa escolhe; ex.: "25,00" fixa o valor)
  O QR Code da janela do Pix é gerado no navegador a partir do código
  configurado: trocou o código, o QR acompanha sozinho.
  Sem nada preenchido, o botão não aparece, mesmo dentro das datas.
  Código Copia e Cola com erro de digitação (CRC inválido) também esconde o botão.
- lojaUrl: endereço da loja (https://...). Vazio = "Em breve".

Se o config.json ficar com erro de sintaxe (vírgula faltando etc.), a página
continua funcionando normalmente, apenas sem o Pix.

PUBLICAÇÃO NO GITHUB PAGES (uma vez só)
1. Crie uma conta gratuita em github.com.
2. Crie um repositório PÚBLICO (ex.: bullrock-site) e envie todos estes
   arquivos para a raiz, inclusive .nojekyll
   (botão "Add file" > "Upload files", arrastando o conteúdo do ZIP).
3. Settings > Pages > Source: "Deploy from a branch" > branch main, pasta / (root).
   O site fica em https://SEU-USUARIO.github.io/NOME-DO-REPOSITORIO/ para testes.
4. Para usar o domínio: Settings > Pages > Custom domain: bandabullrock.com.br
   (o GitHub cria o arquivo CNAME sozinho).
   Depois que o certificado for emitido, marque "Enforce HTTPS".

DOMÍNIO bandabullrock.com.br (no registro.br, editando a zona DNS)
- 4 registros A para o domínio principal (bandabullrock.com.br):
    185.199.108.153
    185.199.109.153
    185.199.110.153
    185.199.111.153
- 1 registro CNAME: www -> SEU-USUARIO.github.io
- Não apague registros MX, se o domínio tiver e-mail.
- Confira esses IPs na documentação do GitHub Pages ("Managing a custom
  domain") antes de configurar.
- Recomendado: verificar o domínio em Settings da conta > Pages > Verified
  domains, para ninguém mais conseguir usá-lo no GitHub.

FOTOS DOS INTEGRANTES
As fotos atuais são provisórias. Substitua os arquivos em images/integrantes/
mantendo exatamente os nomes: bimba.jpg, du.jpg, geleia.jpg, mapola.jpg, toco.jpg.
Ideal: foto quadrada, cerca de 600x600 px, até ~150 KB, rosto centralizado
(a imagem é recortada em quadrado automaticamente).
Nomes, funções e descrições ficam no index.html, no bloco "Integrantes".
O endereço .../#integrantes abre a lista direto (é o que o botão de
compartilhar envia).

AO ATIVAR O DOMÍNIO
No index.html, troque https://tocoduarte.github.io/bandabullrock/ por
https://bandabullrock.com.br/ nas linhas canonical, og:url e og:image
(há um comentário marcando o lugar). Os botões de compartilhar já usam o
endereço atual sozinhos.

ALTERAR DATAS OU PIX
Abra o config.json no github.com (funciona no navegador do celular), toque
no lápis, edite e clique em "Commit changes". O site atualiza em 1 a 2 minutos.

ATENÇÃO
O repositório é público (exigência do plano gratuito) e o histórico de
alterações também. Nunca coloque no repositório nada além do que já aparece
no site (chave Pix e código Copia e Cola são públicos por natureza).

O arquivo _headers só tem efeito no Cloudflare Pages; no GitHub é ignorado.
O arquivo web.config só serve para testar no IIS (tipos .webp, .woff2 e .json);
no GitHub Pages também é ignorado.
